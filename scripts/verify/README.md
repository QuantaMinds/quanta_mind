# scripts/verify/ — what runs, and the one thing that does not

`just verify` runs against real repositories today. It did not for a long time, and the reason it
gave was wrong.

## What runs

| Script | Recipe | Proves |
|---|---|---|
| `build_pack.py` | (used by the two below) | clones a real repository and builds a pack through the product's own code path |
| `assert_no_source_in_pack.py` | `just verify-no-source-leak` | ARCHITECTURE.md invariant 6 — no stored value over 40 chars appears in any source file |
| `assert_deterministic.py` | `just verify-determinism` | invariant 5 — indexing the same history three times produces one pack digest |

Both are known-answer tested: planting a real line from `logging.py` into the pack makes the
source-leak check name the table, the column and the file it came from.

## One check that passed by luck for a week

`assert_deterministic.py` compared every column of every table, including `repo.first_seen`, which
is written from the clock. Two builds a second apart differ. It passed anyway — **both runs kept
finishing inside the same second** — and only failed once a slower run crossed a boundary.

Wall-clock columns are now excluded **by name** and the names are printed on every run, so the
exclusion cannot grow without someone reading it. The list lives in `scripts/verify/volatile.py`
and is shared: `verify-data` will need exactly the same exclusions, and two copies of a list that
must agree is the drift pattern in miniature. Everything the ranking depends on — every row of
`touch` — is still compared.

**This is also why `verify-data` cannot simply be switched on.** A golden pack would never match a
build containing a wall-clock column, so the golden has to be defined over the same exclusions.

## What does not run, and why

`just verify-data` diffs a produced pack against a **reviewed golden** pack. `store/` now produces
a pack, but nobody has reviewed one, so there is nothing to diff against. Committing a pack
generated by the code under test would make the recipe compare the output to itself — green
forever, proving nothing.

It therefore refuses with that reason and is **not** part of `just verify`, which prints what it
did not cover rather than implying completeness.

## The gate that outlived its reason

Until this change, `just verify` refused to run **anything**, on the grounds that all product code
was blocked behind the correlation test reporting a verdict. That test reported one: it was NULL,
it killed the earlier product, and this one inherits none of it. The gate stayed, and with it
`AGENTS.md`'s definition of done — item 1, "`just verify` is green" — was unsatisfiable by anyone.

**A green `just check` still says nothing about whether the data is right.** That distinction is
`docs/engineering/VALIDATION.md`'s subject and it survives this change intact.
